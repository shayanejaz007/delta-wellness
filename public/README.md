# /public — media

## Already here

- `hero-poster.jpg` — 1920×1080 desktop hero plate
- `hero-mobile.jpg` — 900×1400 portrait crop, served below the `sm` breakpoint

Both are generated by `scripts/make-hero-art.py`. They are deliberately
abstract: a light field with signal traces and the amber regulation band. No
anatomy, no equipment, no depiction of any device or procedure. Re-run the
script to regenerate them:

```bash
pip install pillow
python scripts/make-hero-art.py
```

The palette in that script is pulled from the same values as the site's CSS, so
the plate blends into the page background with no visible seam.

## Adding a video later (optional)

The hero looks finished without one. If you want motion:

1. Save your clip here as `hero.mp4` (and optionally `hero-mobile.mp4`).
2. Set `NEXT_PUBLIC_HERO_VIDEO=1`.
3. Restart.

`hero-poster.jpg` is already the poster frame, so there is no layout shift and
no blank box while the video loads. Keep desktop under ~4 MB and mobile under
~1.5 MB, or you will undo the performance work.

## Making the loop seamless

The hero plays the clip forward, then scrubs it backwards, then forwards again,
so it never snaps from the last frame to the first. That reversal is done in
JavaScript by stepping `currentTime`, because no browser supports negative
`playbackRate`.

How smooth the reverse pass looks depends on keyframe density in your encode.
If it looks steppy, bake a true palindrome instead — one clip that already
contains forward + reverse, which then loops natively and perfectly:

```bash
# Build a forward+reverse palindrome
ffmpeg -i source.mp4 -filter_complex \
  "[0:v]split[a][b];[b]reverse[r];[a][r]concat=n=2:v=1[out]" \
  -map "[out]" -c:v libx264 -crf 26 -preset slow -pix_fmt yuv420p -an \
  -movflags +faststart hero.mp4
```

Then in `components/home/Hero.tsx` pass `pingPong={false}` — actually simpler:
swap `<PingPongVideo …/>` for a plain `<video autoPlay muted loop playsInline>`,
since a palindrome needs no scripting at all. That is the highest-quality
option and costs the least CPU.

Dense keyframes also help the scripted version:

```bash
ffmpeg -i source.mp4 -g 12 -keyint_min 12 -sc_threshold 0 \
  -c:v libx264 -crf 26 -preset slow -pix_fmt yuv420p -an \
  -movflags +faststart hero.mp4
```
